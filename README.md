# 拼模台

在自己电脑上查看模型、识别连通部件、检查网格、调整摆位并记录打印进度。适合白模拆件和已有散件的人工拼装整理。模型分析在浏览器本地执行，使用时无需账号、付费 API 或联网。

## Windows 用户

在本仓库的 **Releases** 页面下载 `Pimotai-版本-Windows-x64.zip` 和 `SHA256SUMS.txt`。解压整个文件夹，双击其中的 **拼模台.exe**，浏览器将自动打开。客户包内置运行环境，无需安装 Python 或 Node.js，也无需管理员权限。

请先核对同一 Release 的 SHA256 校验值；详细步骤见 [安装说明](docs/安装说明.md)。需要豆包等 AI 助手协助时，将 [AI 安装指引](docs/AI安装指引.md) 和本仓库地址一起交给它。仓库自动生成的 `Source code.zip` 是源码，不是 Windows 客户包。

## 可以做什么

- 导入 STL、OBJ、3MF；保留模型的装配坐标，识别断开的网格实体。导入不保留原始颜色、材质或贴图，按连通部件重新分配纯色。
- 查看尺寸、面数、开放边和非流形边；部件配色、爆炸展开、旋转查看。
- 按同源、同尺度参考提出摆位候选；人工移动、旋转、缩放、撤销并确认位置。
- 标记逐件打印进度；导出 `.pmt` 工程备份，载入工程继续工作。
- 用带缩略图、文件名和打印按钮的连线卡片查看零件；全部卡片可在模型两侧滚动浏览，也可只显示选中件或关闭标签。隐藏及待定位部件保留状态说明，不自动加入装配。
- 逐件“加入装配”或“从装配隐藏”，区分已有原件与当前展示的装配；状态随工程保存。
- 导出所选部件的显示 STL 和装配 3MF，交给切片软件继续处理；3MF 导出保存当前可见装配的部件配色，最多50万面。
- 载入可选的本机项目包；原件齐全时，可下载原件或点击交给已安装的 Bambu Studio 打开。
- 默认使用浅色界面，可切换深色；导出横屏或竖屏的360°旋转、装配→展开展示视频（WebM，需浏览器支持）。

先点击“体验示例”熟悉操作，再导入自己的文件。独立实体只表示网格连通关系；连续焊接成一个壳的模型，不能仅凭几何自动拆成有语义的零件。无参考的随机散件不能保证自动复原装配；重复件和对称件需要人工核对。尺寸检查不等于装配强度、可穿戴或打印可行性验证。

STL 没有单位，默认按毫米解释；请在“分析”中与原软件核对。首版 3MF 导入仅支持单模型文档的 core 结构和支持的摆位信息；未知厂商的多文档装配可先在原软件中导出 STL 再导入。不保留切片参数、原始材质和贴图，也不支持全部扩展。开放壳不显示可靠实体容积。

单批导入最多64个文件、150MiB，单文件分析最多200万面；整个工程加参考模型最多800万面。`.pmt` 解压后总量最多384MiB，普通3MF预检解压总量仍限200MiB。装配3MF导出最多50万面，超限时应逐件导出显示STL，或使用登记原件切片。这些是不同步骤的上限，大工程可查看不代表一定能整体导出3MF；分批导入也不能绕过单文件和工程总量限制。大型模型还取决于电脑内存和浏览器能力。

## 保存与隐私

网页和依赖随软件附带，模型由本地 Worker 处理，不上传服务器。启动器只监听 `127.0.0.1`，提供网页、健康检查和本机项目清单中登记的文件，不开放任意本地路径读取或上传接口。点击“在拓竹中打开”时，仅把登记原件交给固定安装位置的 Bambu Studio；此操作不发起打印、登录或远程控制。

当前工程缓存在浏览器 IndexedDB，几何数据单独保存，配色、摆位和打印状态改变时增量更新，避免每次重新压缩整个大工程。缓存不是长期备份。关闭无痕窗口、清理网站数据、换浏览器或因端口占用改用另一地址，都可能看不到原缓存。

请定期点击“导出工程”，妥善保存下载的 `.pmt` 文件；它仍是全量压缩备份，导出时会检查压缩后不超过150MiB，大工程需要较多内存与时间。新浏览器或新版本通过“打开工程”恢复；仅导出STL或3MF不包含全部项目状态。

## 可选本机项目

通用发行包不附带用户模型。若另有合法取得的本机项目包，将其解压到 **EXE 旁边的 `本机项目` 文件夹**，再启动工作台。不要放进 `_internal`。源码运行时，默认读取 `server.py` 旁的同名文件夹；也可用 `--projects-dir "项目根目录"` 指定其他位置。没有本机项目时仍可正常导入、查看及保存自己的模型。

每份项目保存在单独子目录，例如：

```text
本机项目/
  示例项目/
    manifest.json
    project.pmt
    originals/
      part-1.stl
```

`manifest.json` 登记项目 `id`、`title`、`projectFile`、`attribution` 和 `files`（每项含 `id`、`name`、`relativePath`）。路径必须相对该项目目录，原件仅接受 STL、OBJ、3MF。项目清单在启动时读取，补齐或更换项目包后请重启工作台。缺失原件不影响已有 `.pmt` 的查看，但不能把工作台预览当作原始文件；“在拓竹中打开”仅对本机存在且登记过的原件提供。

本机模型的许可和署名以各自来源及项目包为准，不随程序获得 MIT 授权。可按模型原许可另行提供非商业项目附包，保留作者署名、来源链接、原README/许可与改动说明。公开源码 ZIP、通用 Windows ZIP 和通用GitHub发布均不自动包含 `本机项目`；分享或升级时分别保管程序与项目包。

## 源码运行与验证

开发环境需要 Python 3.12+；几何测试另需 Node.js 22+。网页依赖已随源码附带，不需要 `npm install`。

```powershell
python server.py
python server.py --no-browser --port 18777
python server.py --projects-dir "其他本机项目目录"
python -m unittest discover -s tests -p test_server.py
node --test tests/*.test.mjs
```

也可运行 `tools/run_dev.ps1`；自定义解释器用 `-Python "你的Python路径"`。默认打开 `http://127.0.0.1:18777/`，端口被占用时自动选择后续可用端口。请使用启动窗口实际显示的地址。关闭启动窗口或按 `Ctrl+C` 即退出；关闭浏览器标签不会停止启动器。

## 构建 Windows 便携包

在 Windows x64 上使用 64 位 Python 和 Node.js：

```powershell
python tools/build_windows.py
```

脚本验证公开源码边界、运行服务与几何测试，将固定版本 PyInstaller 安装到项目内的 `.local/builddeps`，构建自包含目录，并实际启动 EXE 检查网页、ES Module、Worker 和资源。它不修改全局 Python 环境。首次构建需联网下载构建工具与运行环境第三方许可文档，随后保存在 `.local` 缓存。

产物在 `release/`：Windows x64 ZIP、经过白名单筛选的源码 ZIP、`SHA256SUMS.txt`。可单独执行 `python tools/build_windows.py --source-only` 检查并导出公开源码。源码包只纳入程序、通用测试和公开文档；依赖本机私有数据的迁移测试不随包分发。通用包排除 `本机项目`、`宣传片`、`钢铁侠素材`、本机备份、生产笔记、私人模型、影视素材和 AI 模型权重。发布仓库时也应使用该源码包内容，不能直接上传整个工作目录。

GitHub Actions 的“Build Windows release”支持手动构建并保留产物；推送与 `package.json` 版本一致的 `v版本号` 标签会构建并发布 Release。工作流只使用 GitHub 自带的短期凭据。首次发布者须将经过检查的源码提交到自己的仓库，客户下载安装不需要 GitHub token。
